# v1.3.1 数据库部署与验收说明

本页用于在独立环境执行 PostgreSQL 16、Redis、Celery、MinIO 和 Web/API 的数据库工程验收。验收数据全部为固定种子构造数据，不能装入开发库、现场 SQLite 库或企业试用库。

## 1. 准备环境

准备 Docker Engine 与 Compose v2，并确保至少有 4 CPU、16 GiB 内存和足够磁盘。项目根目录执行：

```bash
python3 scripts/init_env.py
docker compose config >/dev/null
```

`init_env` 会创建权限为 0600 的数据库 owner、app、readonly、backup、JWT、MinIO、监控和集成密钥文件，不覆盖已有文件。应用、迁移、只读采集与备份分别使用 `productmatch_app`、`productmatch_owner`、`productmatch_readonly` 和 `productmatch_backup`。

生产或企业试用环境还需启用 TLS、网络访问控制、企业密钥托管和备份加密；这些不是本 Compose 单机验收自动完成的事项。

## 2. 一键隔离验收

输出目录必须是绝对路径且尚不存在：

```bash
python -m scripts.stack_drill \
  --output /absolute/path/to/product-match-acceptance-20260910
```

默认数据规模是 2 个组织，每组织 50,000 条标准商品、10,000 条来源、总计 10 名用户和 10 个逐次替代的历史发布版本，随机种子为 1309。脚本会完成：

1. 静态预检、固定数据和独立真值生成。
2. owner 账号迁移，app 账号迁移结构回归及 DDL 拒绝检查。
3. 数据加载、匹配、`ANALYZE`、代表性命中/空结果/短词 SQL 计划采集。
4. 角色、表、索引、约束、会话参数、活动连接、锁、WAL、检查点、库表大小和脱敏慢查询统计采集。
5. Redis 中断后发件箱补投、PostgreSQL 不可用时不返回假成功、MinIO 中断后失败文件不可下载及恢复重试。
6. 停止业务写入形成恢复点，以 backup 账号备份数据库和对象；停止源 PostgreSQL/MinIO，再恢复到独立实例和独立卷。
7. 以 app 账号核对所有表行数、Alembic 版本、全部对象清单和所有数据库引用对象的 SHA-256，并创建交付暂停标记。
8. 保存命令日志、JUnit、镜像清单、故障时间线、RPO/RTO 和恢复对账，清理隔离栈并将成功证据设为只读。

`--skip-faults` 或 `--skip-restore` 只用于排查，不可作为完整数据库验收结果。`--keep` 会保留容器，证据不会自动冻结；排查结束后需清理唯一项目并重新执行正式运行。

## 3. 证据读取

正式运行至少检查：

| 路径 | 内容 |
| --- | --- |
| `run-manifest.json` | 运行编号、提交、数据、镜像和剩余验收项 |
| `migration/` | 迁移日志、当前版本、漂移检查和完整结构 |
| `dataset/` | 固定种子、规模、真值分布和文件摘要 |
| `correctness/` | 迁移结构 JUnit 与并发、隔离、幂等覆盖说明 |
| `plans/` | 脱敏参数类别与 PostgreSQL `EXPLAIN ANALYZE` JSON |
| `capacity/postgres-stats.json` | 会话、锁、阻塞、WAL、检查点和表/索引体积 |
| `faults/` | 依赖中断时间线与容器日志 |
| `restore/verification.json` | 独立恢复、行数、对象、RPO/RTO 和交付暂停核对 |
| `security/roles.json` | 角色属性、应用权限和 DDL 拒绝结果 |

证据目录不包含密码或密钥值。私密目录必须由验收负责人按企业规则保管或销毁，不能随报告分发。

## 4. 仍需单独执行

自动入口尚不代替以下现场工作：

- 在固定资源下完成预热 120 秒加稳定阶段 30 分钟的混合负载，并保留 P50/P95/P99、吞吐、所有容器资源和两个重叠大任务结果。
- 在审核、分块提交、发布三个阶段分别中断 PostgreSQL；在上传和发布制品生成阶段分别中断 MinIO。
- 终止正在执行任务的真实 Celery 子进程，保持 120 秒自然租约，不人工改到期时间。
- 为 Prometheus/Grafana 指定真实处理人和通知渠道，完成一次告警触发、接收、定位、恢复和解除。
- 在目标环境记录不可变镜像摘要、TLS、网络边界、备份加密、WAL 归档与密钥恢复流程。

这些项目通过后，结论上限是“数据库工程达到企业试用准入水平”。真实 ERP、授权客户数据准确率、真人效率、正式生产容量、高可用和合规验收仍需独立完成。
