# 优化版使用说明（1.1）

优化版在原有上传、人工复核、导出和版本追溯流程上增加异步导入、补数草稿、稳定编号比较、完整策略评测及运行状态。默认仍采用规则匹配，学习模型保留实验状态。

## 本地启动与升级

新安装解压后，安装 `requirements.lock` 中的依赖，运行 `python -m scripts.dev --seed`，打开 `http://127.0.0.1:18765`。交付包内含已构建网页。演示密码 `Demo2026!match`；账号为 `operator@demo.local`、`reviewer@demo.local`、`admin@demo.local`。`scripts.dev` 在 macOS 中会检测虚拟环境附带的 OpenMP 库路径，供影子模型计算使用。

已有 1.0 本地数据时，先停止原 API 和 Worker，再执行：

```bash
python -m scripts.upgrade --backup /path/to/new-backup
python -m scripts.dev
```

升级工具先备份，只有数据库结构与已知初始结构或当前结构完全一致时才登记 Alembic 版本；未知结构会停止并保留备份。之后执行增量迁移和模型漂移检查。项目本次本地数据已经完成升级，不需要再次执行。备份目的目录必须为新目录。

## 异步导入与映射复用

1. 上传文件后即登记后台解析任务。页面显示等待、解析或校验状态，处理失败可点击“重试后台处理”。关闭导入弹窗不会取消已经入队的任务。
2. 选择工作表、表头并确认字段映射。填写供应商名称后可以“保存映射模板”。同名模板的字段变化产生新版本；相同配置不会重复建版本。
3. 选择已保存模板可复用列名映射。表头变化时先显示确认提示，只保留仍存在的列，请补齐其余字段。
4. 校验完成后查看全部分页结果，可“仅看问题行”或下载完整问题清单。错误行仍需明确确认排除，标准库错误必须修正后才能发布。

解析缓存按组织、文件哈希、编码、文件类型和解析器版本隔离；校验缓存另绑定工作表、表头、映射、品类和规则版本。重复配置会复用缓存，输入创建具有幂等保护。旧版同步校验接口为兼容保留，新界面使用异步接口。

## 补资料与更正

数据专员或管理员在工作台点击“待补资料”，也可选中一条记录点击“补充本条资料”。问题清单包含需复核、规格冲突、暂无候选和退回补充的记录，可以下载仅包含这些行的 CSV 模板。

表单显示来源表格原有字段。填入经资料核实的值，注明供应商说明、规格单或其他依据，保存本条草稿。草稿按操作人分别保存，版本冲突时需重新读取。界面不会把候选商品字段自动写入来源字段。

提交选定草稿后生成独立的补数输入版本和运行，仅匹配本次修正记录。例如原任务 1 万条、20 条需补数，提交后得到包含 20 条记录的补数运行。原始行和补数依据可追溯，原输入、原审核和旧导出保持历史含义；补数记录仍需另一位审核员确认。

**补数运行是明确标注的子集，其导出只含该子集。当前不自动合并为原任务的全量最新映射，也不复制原审核决定。** 如需同一文件的全量新版本，仍可通过“导入修正版输入”创建完整版本。对外使用补数导出时，应结合原运行编号识别其范围。

审核时可点击“下一条待处理”，或使用 `Alt + J`。列表先加载摘要，当前选中的记录再读取完整候选与依据；切换记录期间确认按钮锁定，避免误操作。

## 版本比较

同一供应商批次内以唯一、非系统生成的来源编号对应记录。单纯重排文件不会产生业务变化。结果区分新增、移除、字段修改、身份字段变化、候选变化与审核变化，支持继续加载。缺失编号或重复编号进入歧义列表，不自动建立对应关系。直接比较补数运行与其父运行时，仅比较涉及的来源记录。

商品库、成员、历史批次和审核历史均支持继续加载；可以按商品库名称、姓名、账号、批次或供应商搜索。运行比较按同一批次筛选，不受其他批次挤占首屏的影响。

## 策略评测与影子对照

管理员进入“组织设置 → 策略评测”。发布学习策略必须绑定已登记的完整策略评测，不能单独修改阈值后套用旧报告。策略绑定模型、冻结词表、标准化与打分代码哈希、特征顺序、校准器、召回参数、推荐阈值、候选分差及评测数据版本。

评测登记命令见 `标注与试用规范.md`。本次交付的本地工作空间已登记受控模拟报告；新演示数据库可按该文档登记。模拟数据不具备业务准入资格，因此发布按钮关闭。可以对已有成功运行做影子比较，查看首选变化、推荐数、冲突数及与现有人审结论的不一致数。影子计算不写入有效映射或导出快照。

切回旧策略时，在“匹配与复核”选择旧版为默认策略，只影响之后创建的运行。历史运行仍保留自己的策略清单。

## 运行状态与恢复

管理员在“运行状态”查看待处理事件、最老等待时间、租约、到期文件清理和导入失败原因。`/api/v1/metrics` 提供低基数 HTTP 延迟、状态码、存储错误及数据库队列指标；`deploy/alerts.yml` 为 Prometheus 告警规则样例，采集时需要管理员认证。HTTP 指标是当前 API 进程的指标，重启会清零；任务与清理状态持久保存在数据库。

到期导出每小时检查并入队清理；删除可重试，保留导出快照、哈希、元数据及删除时间。系统检查其他对象引用后才删除物理文件。运行调度器和存储正常时，目标是在到期后 24 小时内清理；停机和存储失败期间不能承诺这个期限。

本地备份包含数据库、对象、模型、冻结词表、评测数据、会话密钥和运行版本信息。恢复到新目录后配置稳定模型根目录：

```bash
python -m scripts.backup create /path/to/new-backup
python -m scripts.backup restore /path/to/new-backup /path/to/restored
DATA_DIR=/path/to/restored MODEL_DIR=/path/to/restored/models python -m scripts.dev
```

生产栈仍需现场验收。可用 Docker 环境中运行 `python -m scripts.stack_drill`，会建立独立的 `product-match-acceptance` 项目，执行 PostgreSQL、Redis、Celery、MinIO、Nginx 的核心闭环和真实 Redis 中断验证。凭据和日志写入 `work/stack-acceptance`，不包含在交付包。该脚本本轮未实际执行。Worker、数据库、对象存储的生产故障演练，以及 4 核 16GB 的双 Worker 大规模测试仍见优化验收报告中的待验收项。
