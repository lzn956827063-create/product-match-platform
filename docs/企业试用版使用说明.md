# 商品数据匹配平台 v1.2 企业试用版使用说明

本轮依据《企业试用优化方案》实现。当前可在本机完成数据核对、多人审核、完整发布、模拟系统交付及恢复验证。生产式容器部署和真实业务收益仍待验收，详见 [验收报告](企业试用优化验收报告.md)。

## 从哪里使用

打开 http://127.0.0.1:18765，刷新页面并重新登录。左侧新增 **发布与协作**，其中有批次发布、审核协作、标准库影响、供应商质量、系统交付、独立标注六个入口。工作台右上角的 **批次完整发布** 可直接进入当前批次。

首次安装演示环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
python -m alembic upgrade head
python -m scripts.seed
python -m scripts.demo_enterprise
python -m scripts.dev
```

仅在演示环境运行 seed 和 demo_enterprise。已有环境升级见 [运行与验收](企业试用运行与验收.md)。演示账号密码沿用 `Demo2026!match`，真实使用请创建自己的组织和成员。

## 完整交付一份批次

1. 数据专员导入完整供应商表并完成匹配；审核员核对每条商品，明确选择已匹配、无匹配或需补资料。
2. 问题行在补数工作台提交，生成只含修正记录的新运行；再次独立审核。补数草稿尚未提交时不参与正式结果解析。
3. 进入批次发布，选择完整输入运行。系统沿来源关系合并补数，完整结果保留未改变记录原有的审核依据。
4. 缺号、重号、编号复用需要明确来源身份；多个补数末端需要选择有效分支并说明原因。未审核、待补充或已撤销的有效末端会阻断发布，页面显示具体问题。
5. 校验通过后由发布者确认发布。发布时再次检查批次结果版本；校验后发生变化需重新校验。
6. 文件就绪后下载：**完整核对结果**包含已匹配、确认无匹配及明确排除；**仅有效映射**只含确认匹配；**增量变更**相对明确基线，使用 upsert、delete、invalidate。

例如：原始 1 万条加 20 条补数，完整发布仍为 1 万条，20 条引用新的审核决定。下一份完整输入移除 5 条时，确认范围变化后生成 5 条删除/失效变化。补数子集不会被当作完整替换文件。

已发布内容及 CSV 字节不可修改。后续发布可以替代旧版；主动撤销会单独记事件。引用的决定发生变化时，旧发布标记失效并通知接收方，旧文件仍可核验原哈希。

## 多人审核

主管按批次、供应商、问题类型筛选，最多一次分派 100 条，转交或退回需记录原因。责任人和当前领取人分别展示。

审核员领取后进入对应来源记录。默认领取 5 分钟，页面每分钟续期；离开记录可释放，关闭或断网后到期允许重新领取。恢复自己的领取会更换令牌。主管转交后，原令牌不能继续提交。批量审核逐条报告失败，成功项继续保留。

管理员在“审核协作 → 协作规则与组织配额”配置强制领取、期限和配额。为兼容旧 API，迁移组织默认未开启强制领取；已有分派或有效领取始终检查资格，网页审核始终先领取。要求所有接入客户端使用领取时，请开启强制领取。

| 角色 | 新增操作 |
|---|---|
| operator 数据专员 | 创建发布草稿、补数、来源身份确认 |
| reviewer 审核员 | 领取、核对、提交和撤销审核 |
| supervisor 审核主管 | 分派、转交、退回 |
| publisher 发布者 | 完整发布、重试发布文件、撤销发布 |
| integration_manager 集成管理员 | 机器凭据、通知目标、交付重放 |
| annotator 标注员 | 独立提交标签 |
| adjudicator 裁决员 | 两人分歧后的第三人裁决 |
| admin 管理员 | 成员、标准库影响与启用、供应商、数据集及配额管理 |

角色可组合。管理员、主管、发布者均不会自动获得审核权限；双人复核下，批次/输入/运行提交者不得审核自己的记录。演示管理员已额外赋予发布、主管、集成和裁决权限，仍不兼任审核员。

## 标准库变化与供应商质量

标准库影响页先选择前后版本，确认商品身份一对一对应，再后台分析。相同 SKU 字符串只作为人工核对线索，不自动建立商品身份。页面采用虚拟选择列表支持较大标准库。

身份规格变化、停用和编码变化产生待办；展示字段变化产生通知。影响清单列出实际引用的映射与发布版本；替代商品必须经新版本运行和审核，旧映射不被自动覆盖。分析完成且新库已发布后，管理员可启用为新任务默认版本。旧发布仍保留原库版本依据。

供应商先建立稳定身份，再人工确认历史名称、批次和模板归属。同名不会自动合并。质量页展示缺字段、重复编号、规格冲突、首次完整审核率、补数轮数和处理耗时，显示分子、分母、数据版本和问题明细。补数子集单独标注；无匹配不会直接算供应商错误，不提供混合总分排名。

## 系统交付

集成管理员创建有范围和到期时间的服务账号，凭据只显示一次，可轮换、停用。创建通知目标时签名密钥也只显示一次。生产目标必须是配置白名单中的 HTTPS 地址，禁止任意内网地址及重定向。

文件就绪后后台发送带 event_id、时间戳和 HMAC 签名的通知。接收方读取全量或明确基线增量，核对 SHA-256，再用服务账号提交业务回执。HTTP 2xx 只使状态变为 RECEIVED；只有有效回执才能变为 APPLIED。PARTIAL 必须逐条列出失败 stable_key 和原因。

临时失败自动退避重试，最多 8 次后转人工处理。修复后重放保留 event_id；接收方必须去重。撤销和失效使用独立事件。项目提供 `scripts.mock_receiver` 作为本机采购协议模拟器，当前模拟器使用全量同步；平台另有增量接口。这不代表任何真实 ERP 已接入。

接口说明位于 `/api/v1/docs`，服务账号使用 `Authorization: Bearer <credential>` 和 `X-Organization-ID`。接口包括 `/service/releases`、`/service/releases/{id}/artifacts/{kind}/download`、`/service/releases/{id}/delta?base_release_id=...`、`/service/deliveries/{id}/receipt`。

## 独立标注与实验

管理员登记数据来源及证据、实体分组规则，添加来源与标准商品候选对。两名不同标注者在不展示推荐分数和其他人的决定的界面判断同一 SKU、不同 SKU或资料不足；分歧由第三人裁决。资料不足不会转换成负例。来源资格是上传者声明，平台不会据此声称已核验真实授权。

实体固定分到训练、验证、测试；相同标准化来源必须同组，近重复及别名仍需数据管理员核实分组。全部完成后冻结清单、标签、参与者、时间与哈希。冻结不代表模型准入。

训练池可使用随机、不确定性或规则与模型分歧选样，保留 20% 随机预算。模型选样前须选择已登记的冻结评测模型执行训练池评分。实际人工分钟数未知时保留空值，不由样本条数估算。当前三策略模拟实验持平，学习策略继续保持实验状态。
