# 商品数据匹配与核对平台产品方案

版本 1.0　日期 2026年9月10日　适用阶段 首个可交付版本

本方案面向项目开发者及试用业务人员，定义商品目录匹配的业务边界、功能、页面、权限和验收方式。首版服务采购及运营人员：将供应商商品表映射到企业标准商品库，识别规格冲突，通过人工审核生成可追溯的映射结果。

项目以公开数据开发和验证算法，以可部署的软件展示企业工程能力。文中性能、效果和工期均为规划目标，实施后应记录实测结果。配套技术方案规定具体实现和实验协议。

## 1 产品定位与业务价值

### 1.1 目标用户与工作场景

采购或运营人员定期收到不同供应商的商品表，需要找出每条记录对应的内部商品。供应商编号通常不能直接关联内部编号；名称还可能包含简称、不同单位和缺失参数。依靠表格精确查找会漏掉相同商品，仅依据名称相似度又可能关联错规格。

平台将这项工作拆为字段整理、候选推荐、人工审核和结果导出。首版集中在手机、存储设备等有清晰品牌、型号和规格的电子商品；验收时固定一个子类别，先证明效果，再扩大品类。

| 角色 | 日常任务 | 期望结果 |
| --- | --- | --- |
| 数据专员 | 导入供应商表，配置字段，提交匹配 | 减少逐行搜索和手工关联 |
| 审核员 | 核对候选、处理冲突、确认结果 | 快速找到依据，避免错误规格关联 |
| 组织管理员 | 维护成员、角色、标准库和规则配置 | 控制使用范围，追踪变更 |
| 只读成员 | 查询任务和下载已授权结果 | 获得来源明确的业务数据 |

### 1.2 业务示例

以下记录是用于解释规则的示例。标准库商品为“A牌 X5 手机 8GB 128GB 黑色”。供应商记录“A牌X5 黑色 8+128”可以成为匹配候选；“A牌X5 黑色 12+256”必须标记规格冲突。“A牌X5 黑色”缺少关键规格，进入人工补充或复核。

输出保留供应商原始编号、原始名称、对应内部商品编号、审核结果及差异说明。平台不根据相似名称擅自合并原始记录。

### 1.3 验证业务价值

首轮试用招募2至3名有采购、商品维护或表格整理经验的人，在同一批数据上比较纯人工处理与工具辅助处理。交换任务顺序或使用难度相近的两组数据，减少记忆造成的偏差。记录每百条处理时间、错误关联数、人工复核条数和主观困难点。未完成试用前，不宣称节省时间或获得企业采纳。

## 2 范围与商品身份规则

### 2.1 首版范围

| 优先级 | 功能范围 | 交付要求 |
| --- | --- | --- |
| P0 必须完成 | 登录与组织权限、标准库、表格导入、字段映射 | 可以准备一组合法的匹配输入 |
| P0 必须完成 | 规则基线、训练得到的匹配模型、候选推荐 | 可以比较算法并展示逐条依据 |
| P0 必须完成 | 人工审核、映射版本、结果导出、任务恢复 | 形成完整业务流程 |
| P1 验证后扩展 | 语义召回、已审核映射复用、重复商品建议 | 在基线稳定后单独验证收益 |
| P2 后续研究 | 小模型微调、主动学习、外部系统连接 | 依据实验与试用反馈安排 |

首版接收 .xlsx 和 .csv。标准库与供应商表各自选择一个工作表，导入后生成不可变的数据版本。首版通过文件交付映射结果；自动写入ERP、发票核验、采购付款、图片识别和任意品类商品匹配属于后续独立范围。

### 2.2 什么算同一件商品

商品身份由品牌、型号及类别规定的关键规格共同确定。以手机为例，运行内存、存储容量、颜色、销售版本和包装数量可能区分SKU；以存储设备为例，还需容量、接口和形态。类别配置必须明确必核字段，不能用一套宽松规则覆盖所有商品。

| 情况 | 处理规则 |
| --- | --- |
| 品牌和型号明确冲突 | 候选禁止直接确认，先修正数据或另选商品 |
| 关键规格明确不同 | 标记冲突，名称相似也不能抵消 |
| 关键规格缺失或含义不清 | 标记信息不足，允许补充后重新运行 |
| 商品报价不同 | 显示差异；价格不决定是否为同一商品 |
| 单件与套装不同 | 视为不同销售SKU，禁止直接等同 |
| 多条供应商记录对应同一标准商品 | 允许，保留每条记录和供应商来源 |
| 一条供应商记录对应多个标准商品 | 首版不支持拆分；转入人工澄清 |

名称标准化和原始内容分开保存。型号中的数字、连字符和后缀需要保留；未经类别规则确认，不自动将单位相近、地区版本不同或含配件的商品视为同一件。

## 3 用户流程与页面

### 3.1 完整操作流程

1. 管理员或数据专员导入标准商品库并处理错误行，由管理员发布库版本。
2. 数据专员新建供应商批次，上传表格，选择工作表和表头。
3. 配置“原始列对应哪个商品字段”，预览转换结果并确认有效行。
4. 选择标准库版本，提交匹配任务；界面显示排队、处理中和完成情况。
5. 审核员按冲突、待复核、推荐匹配、暂无候选分类处理记录。
6. 审核员确认对应商品或记录“当前未匹配”，填写必要原因。
7. 有导出权限的成员选择已确认映射或全量状态报告，生成结果文件。
8. 修正原始字段、更新标准库或更换匹配方案时，新建运行版本并比较变化。

### 3.2 页面结构

| 页面 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 任务列表 | 供应商、文件、进度、异常数、创建人 | 新建、筛选、查看、重试或取消 |
| 导入向导 | 文件预览、字段对应关系、错误行 | 配置、修正、确认有效行 |
| 标准商品库 | 内部编号、名称、关键规格、库版本 | 导入、预览、发布和查看历史 |
| 匹配工作台 | 来源商品、候选商品、差异和审核状态 | 搜索候选、确认、退回补充 |
| 导出记录 | 导出类型、范围、时间、创建人 | 生成和下载获授权的文件 |
| 组织设置 | 成员、角色、默认匹配方案 | 管理成员和配置 |

### 3.3 匹配工作台交互

左侧显示待处理记录及筛选器，中间保留来源商品的原文和标准化字段，右侧展示最多5个候选及关键字段对比。界面默认显示“型号一致”“容量冲突”“颜色缺失”等可读依据；技术评分放在展开详情中，避免业务人员把分数误认为保证。

批量确认仅适用于推荐匹配且无关键冲突的记录。提交前展示本次选择的明确条数，不以当前分页代替全部筛选结果。信息不足和冲突记录不能被批量确认。审核员也可搜索标准库中未进入推荐列表的商品，记录其人工选择来源。

两人同时修改同一记录时，后提交者收到“记录已更新，请刷新后处理”，界面展示最新结果。更换候选或撤销确认要求填写原因，并保留原决定。

## 4 功能需求

### 4.1 标准库与导入

FR01 标准库：内部商品编号在一个库版本内唯一。发布前检查重复编号、缺失名称及关键字段冲突。初版标准库通过重新导入产生新版本；已有运行始终使用原先选定版本。

FR02 文件接入：单文件规划上限20MB，供应商批次最多10,000条有效行，标准库最多50,000条。超过限制时在创建任务前说明原因。CSV支持UTF-8和显式选择GB18030；用户可选择工作表和表头行。编号按文本处理，保留前导零。

FR03 字段映射：商品名称必填，来源商品编号可选。没有编号时生成批次内记录号，展示为系统记录号。品牌、型号、规格、价格和币种为可选字段，但类别的必核字段缺失会影响审核条件。列名别名可以给出建议，最终由导入者确认。

FR04 数据质量：逐行展示错误和警告。空名称等错误行不参加匹配；重复来源编号、缺失关键规格等进入待处理提示。提交时显示总行数、有效行数、排除行数，并要求确认排除范围。整表无有效行时禁止运行。

### 4.2 匹配与复核

FR05 任务执行：每次运行绑定明确输入和方案版本。进度区分已处理、排除、失败条数。可取消尚未完成的任务；取消后保留状态记录，但不开放该运行的新审核和正式导出。

FR06 候选与证据：记录显示推荐候选、字段依据及关键冲突。没有候选时明确显示“当前未找到候选”，提供标准库搜索入口；不得直接推断企业不存在该商品。

FR07 审核：首版所有正式映射均需人工确认。审核员可确认一个商品、标记当前未匹配、退回补充资料或撤销原决定。确认必须满足无未解决的关键规格冲突；修正来源字段后需生成新数据版本并重新运行。

FR08 历史处理：人工结论以追加记录保存。后续运行可展示历史结果供参考；自动复用作为P1功能，仅在来源身份、内容和标准商品版本仍匹配时启用。人工结论不会直接触发在线模型训练。

### 4.3 导出与追踪

FR09 导出：提供“已确认映射”和“全量状态报告”两种输出。前者只包含当前有效的已确认关系，后者保留未匹配、待补充和未审核记录。导出时展示选择范围及各状态条数，文件内容绑定生成时的审核快照。

FR10 字段：导出包含来源文件、工作表、原始行号、来源编号、原始名称、标准编号、标准名称、差异说明、审核状态、审核人、审核时间和运行编号。原始列可选择保留；来源字段按文本安全输出。

FR11 撤销与留痕：撤销只改变后续导出的有效映射，已经下载的文件无法自动召回。界面标识旧导出所依赖的决定已变化，并支持生成新版本。

FR12 权限：成员停用后立即阻止后续业务访问。任务、商品、审核和下载都按组织授权。任何跨组织编号访问都不能泄漏数据或其存在性。

## 5 状态与权限规则

### 5.1 任务与审核分别管理

| 对象 | 状态 | 允许的后续操作 |
| --- | --- | --- |
| 导入批次 | 待配置、校验中、就绪、校验失败 | 配置、查看错误、生成修正版 |
| 匹配运行 | 排队、处理中、成功、失败、取消中、已取消 | 查看进度、取消；失败后新建重试运行 |
| 匹配建议 | 推荐匹配、需复核、规格冲突、暂无候选 | 进入人工审核，不代表最终关系 |
| 审核记录 | 未处理、已确认、当前未匹配、待补充、已撤销 | 按权限追加下一次决定 |

运行成功表示计算完成，不表示业务审核完成。只有成功运行开放审核和正式导出；失败或取消的部分结果仅供诊断。数据修订不修改历史运行，而是建立新版本。

### 5.2 角色权限矩阵

| 操作 | 数据专员 | 审核员 | 管理员 | 只读成员 |
| --- | --- | --- | --- | --- |
| 导入和启动任务 | 是 | 否 | 是 | 否 |
| 查看组织内业务数据 | 是 | 是 | 是 | 是 |
| 审核和撤销决定 | 否 | 是 | 需兼任审核员 | 否 |
| 发布标准库版本 | 否 | 否 | 是 | 否 |
| 导出已确认映射 | 是 | 是 | 是 | 是 |
| 管理成员和匹配方案 | 否 | 否 | 是 | 否 |

首版组织内共享业务数据，组织间严格隔离；项目级细粒度授权留到后续。用户可兼任多个角色，默认开启双人复核，任务创建者不能审核自己提交的批次，管理员也不能绕过。组织管理员可调整后续任务的复核策略并留痕；已启动任务使用原策略。演示环境使用两套业务账号验证该规则。

## 6 验收标准与效果目标

### 6.1 功能验收

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC01 | 上传含前导零编号、空值和中文列的表格 | 编号保真；错误行可定位；有效行数可核对 |
| AC02 | 同名称但不同容量、颜色或套装 | 冲突可见，不能批量确认为同一SKU |
| AC03 | 无候选或信息不足 | 可人工搜索或退回补充，无虚构匹配 |
| AC04 | 两人同时审核一条记录 | 只接受一个当前版本，另一操作返回冲突 |
| AC05 | 重复提交、执行进程退出和任务取消 | 不重复产生业务结果；恢复路径明确 |
| AC06 | 访问另一个组织的任务和下载 | 无数据泄漏，权限检查失败 |
| AC07 | 导出后撤销映射 | 旧文件有历史标识，新导出排除已撤销关系 |
| AC08 | 切换模型或标准库 | 原运行可复现，新运行有独立版本和差异 |

### 6.2 算法与性能目标

以下为第一轮实验和性能预算，不是已取得的成绩。技术方案规定数据划分、统计口径及失败后的处理方式。

| 指标 | 初始目标 | 核验方式 |
| --- | --- | --- |
| 候选Recall@20 | 至少95% | 在具备完整相关关系的检索评测集上计算 |
| 高推荐组精确率 | 至少98% | 以来源记录的首选匹配计数，报告样本数和区间 |
| 高推荐覆盖率 | 争取达到30% | 分母为全部有效来源记录，同时报告无对应商品比例 |
| 轻量模型收益 | 同等精确率下覆盖率优于规则基线 | 固定独立测试集，并比较召回和耗时 |
| 列表及审核接口 | P95小于1秒 | 4核16GB参考环境，10名模拟活跃用户 |
| 首轮匹配运行 | 1,000条对10,000条在5分钟内 | CPU基线，含预处理和首次建索引；单独报告各阶段 |
| 业务效率 | 通过小样本试用确定 | 记录处理时间与错误数，不预填改善百分比 |

如果数据量不足以支持可靠的精确率结论，保留“需复核”模式，扩充评测后再调整推荐策略。运行上限与性能预算分别管理，必须另测10,000条批次的内存、取消和恢复能力。

## 7 实施计划与交付物

### 7.1 分阶段安排

按单人每周投入约20至25小时估算，首版计划8至10周；先完成规则版本的完整流程，再增加学习模型。学习成本和试用反馈可能影响工期。

| 阶段 | 工作内容 | 阶段完成条件 |
| --- | --- | --- |
| 第1周 | 类别规则、数据集登记、页面草图、验收样例 | 商品身份和数据划分固定 |
| 第2至3周 | 组织权限、标准库、导入、规则匹配 | 两张表可完整运行并查看候选 |
| 第4至5周 | 审核、导出、任务恢复、审计 | P0业务流程可演示 |
| 第6至7周 | 特征工程、模型训练、消融与阈值评估 | 可复现实验报告和模型版本 |
| 第8至10周 | 性能及权限验证、试用、修正和部署 | 验收报告、演示环境、操作说明 |

### 7.2 最终交付

交付可运行代码、Docker Compose配置、数据准备说明、数据库迁移、接口文档、算法训练脚本、评测报告、测试记录和业务演示视频。演示准备两个组织、不同角色以及正常匹配、规格冲突、缺失字段、并发审核和任务重试案例。

试用重点回答三个尚待验证的问题：用户最常处理哪个商品类别；现有商品编号能覆盖多少记录；错误匹配与漏匹配各自造成多少人工成本。根据答案调整类别规则和推荐阈值。
