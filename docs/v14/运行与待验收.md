# v1.4 运行与待验收

## 本地升级

停止旧 API、Worker 和接入轮询器，先创建新的备份目录，再执行迁移和演示配置补齐：

```bash
python -m scripts.backup create /absolute/path/to/new-backup
DB_AUTO_CREATE=false python -m alembic upgrade head
python -m scripts.demo_v14
DB_AUTO_CREATE=false python -m scripts.dev --port 18765
```

目标迁移头为 `75d10e739902`。`scripts.demo_v14` 是幂等操作，只补充演示供应商、已发布映射、接入源、冻结数据集、构造评测和阈值草稿；它不会覆盖已有业务记录。真实环境不要运行 `scripts.seed` 或任何演示初始化。

本地默认使用 SQLite WAL、本地对象目录和 `var/inbox` 接入根目录。可通过 `INGESTION_ROOT` 指定另一个受控根目录。`scripts.dev` 启动三个进程；停止时应确认 API、`workers.dispatcher` 和 `scripts.poll_ingestion` 一起退出。

健康入口：

- `/api/v1/live`：进程存活。
- `/api/v1/health`：数据库可访问并返回应用版本。
- `/api/v1/readiness`：数据库、Redis 队列和对象存储依赖状态。
- `/api/v1/docs`：当前运行版本的 OpenAPI 页面。

## Compose 运行

```bash
python3 scripts/init_env.py
docker compose up --build -d
docker compose exec api python -m scripts.bootstrap --org "你的组织" --email admin@example.com --name "管理员"
```

Compose 的 `ingestion-poller` 服务轮询所有已启用的目录和 S3/MinIO 接入源。`/data` 卷保存本地接入目录，S3 接入读取 `product-match` 桶。应用凭据继续通过 secrets 文件注入。

## 本地复核命令

```bash
python -m scripts.test -q
pnpm -C apps/web build
python -m alembic current
python -m scripts.demo_v14
python -m scripts.poll_ingestion --once
```

macOS 的测试入口会自动定位 scikit-learn 附带的 OpenMP 动态库。直接执行训练脚本时仍需确保 LightGBM 能加载 OpenMP。

只允许迁移建表的完整测试包含 PostgreSQL 角色权限断言，必须连接专用 PostgreSQL 验收库：

```bash
TEST_DATABASE_URL=postgresql+psycopg://... TEST_MIGRATED_SCHEMA=true DB_AUTO_CREATE=false python -m scripts.test -q
```

## 企业目标栈待验收

正式验收必须在带 Docker 的独立 Linux 主机或等价企业环境执行。建议至少 4 核 CPU、16 GiB 内存和 100 GiB 可用磁盘。使用新目录保存每次运行的失败或成功证据：

```bash
python -m scripts.stack_drill --output /absolute/path/to/new-v14-acceptance-run
```

正式结论不得使用 `--skip-faults` 或 `--skip-restore`。完成栈级自动化后，还需要人工补齐：

1. 固定资源、预热 120 秒、持续 30 分钟的混合负载，并同时运行两个 1 万来源任务。
2. 在审核提交、分块持久化和发布校验阶段分别中断 PostgreSQL。
3. 在上传、导出和发布文件生成阶段分别中断 MinIO。
4. 终止真实 Celery 子进程，等待 120 秒自然租约恢复，验证旧执行令牌被拒绝且没有重复有效结果。
5. 将 PostgreSQL 和 MinIO 恢复到新实例，核对所有表行数、迁移头和对象摘要，并记录实际 RPO 与 RTO。
6. 触发接入失败、数据库不可用、对象存储不可用和任务积压告警，保存通知到人、定位、恢复和解除时间线。

建议性能门槛沿用方案：来源列表 P95 不高于 500 ms、审核提交和精确 SKU P95 不高于 300 ms、型号前缀和中文模糊查询 P95 不高于 500 ms、非预期 5xx 和网络错误低于 0.1%、数据一致性错误为 0。

真实 ERP、企业单点登录、高可用数据库、WAL 连续归档、跨主机恢复、授权客户数据和真人试用属于取得企业条件后的 P2 工作。没有这些证据时，构造数据结果不能换算成真实业务准确率、覆盖率或人工节时。
