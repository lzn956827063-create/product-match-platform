# v1.4 使用说明

v1.4 用于企业暂未开放 ERP 时的受控商品文件协作。它把供应商文件接收、映射校验、候选匹配、风险审核、结果发布和交付记录连接成一条可追溯流程。算法只提供审核建议，正式映射仍由有权限的业务人员确认。

## 启动演示环境

在项目根目录执行：

```bash
python -m alembic upgrade head
python -m scripts.seed
python -m scripts.demo_enterprise
python -m scripts.demo_v14
python -m scripts.dev --port 18765
```

打开 <http://127.0.0.1:18765>。`scripts.dev` 同时启动 API、数据库任务执行器和接入轮询器。演示密码统一为 `Demo2026!match`，数据专员、审核员和管理员账号见项目根目录 README。

## 数据接入

1. 使用数据专员或管理员账号进入“数据接入”。
2. 在“映射配置”新建供应商模板，填写文件格式、工作表、表头行和来源列名。
3. 用代表性文件执行“试运行”，核对预计接收数、拒绝数、转换结果和代表性错误。
4. 管理员发布配置版本。之后到达的文件会绑定当时生效的版本；回退会创建新的版本，历史输入保持不变。
5. 在“接入源”建立页面上传、监控目录、S3/MinIO 或受控 API 入口。
6. 在“接入事件”查看去重结果、行级问题报告和每次处理尝试。只有系统处理失败的原事件可以重放；行级错误需修正文件后重新提交。

监控目录必须填写 `INGESTION_ROOT` 下的相对路径。本地默认根目录为 `var/inbox`。轮询器等待文件大小和修改时间稳定后处理，再移入同目录的 `archive` 或 `rejected` 子目录。

S3/MinIO 前缀必须采用 `<组织编号>/<供应商编号>/...`。Compose 中默认桶为 `product-match`，轮询器与 API 共用应用数据卷和对象存储配置。

## 受控 API

先创建 API 接入源并妥善保存只显示一次的签名密钥，再由集成管理员创建含 `ingestion:write` 权限的服务账号。请求使用以下头：

| 请求头 | 内容 |
| --- | --- |
| `Authorization` | `Bearer <服务账号凭据>` |
| `X-Organization-ID` | 接入源所属组织 |
| `X-Event-ID` | 接收方生成的稳定幂等键 |
| `X-Timestamp` | 当前 Unix 秒，允许前后 5 分钟 |
| `X-Signature` | `HMAC-SHA256(secret, timestamp + "." + event_id + "." + body)` |
| `X-Filename` | 带 `.csv` 或 `.xlsx` 后缀的文件名 |
| `X-Profile-ID` | 可选；省略时使用该供应商最新已发布配置 |
| `X-Content-SHA256` | 推荐；请求正文 SHA-256 |

提交到 `/api/v1/service/ingestion-sources/{source_id}/events`。服务端同时校验服务账号权限、组织边界、签名时间窗、文件大小、摘要、事件号和组织级请求限流。

## 智能审核和标签

审核员、管理员或独立标注员可进入“智能审核”。队列优先显示硬冲突、无候选、关键字段缺失和前两名接近的记录，并展示每个风险因素。进入工作台后继续核对原始字段、标准化字段和候选差异。

每次确认、未匹配、退回补资料或撤销都会追加审核事件并生成标签版本。退回补资料默认保持 `HOLD`；存在争议时由管理员或裁决员标记为 `DISPUTED`。这些状态防止未完成结论直接进入训练数据。

## 算法评测和阈值

管理员、独立标注员或裁决员可查看“算法评测”。页面将构造数据、公开数据和授权业务数据分开显示，并列出数据集摘要、样本量、Recall@20、Top-1、nDCG@5、校准 ECE、建议区精确率区间、拒识率、硬冲突和推理 P95。

管理员可基于冻结评测创建阈值草稿。审批时系统检查 Recall@20、建议区精确率及其 95% 下限、ECE 和硬冲突门槛，随后创建新的匹配方案版本。阈值变化只影响新运行。

构造数据指标用于验证算法管线、指标计算和准入控制，不能证明真实手机商品准确率、覆盖率或人工节时。
