# 商品匹配平台交付验收报告

2026 年 9 月 10 日。此次交付形成了可运行的首版业务闭环，包含组织权限、标准库、导入映射、候选匹配、审核、导出、版本与任务恢复。所有结果以下列实测环境和范围为边界。

## 实测环境

macOS 26.6.2，Apple ARM64，8 个逻辑 CPU，16GB 内存，Python 3.12.14。后端使用 SQLite WAL 和本地对象存储，后台为独立数据库任务执行进程。浏览器使用 Chromium，视口 1440×1000 与 390×844。

Python 依赖固定在 `requirements.lock`，前端依赖固定在 `apps/web/pnpm-lock.yaml`。最终运行保存代码内容摘要、依赖锁摘要、输入与标准库摘要、规则/索引/特征/方案/复核策略。

## 性能实测

以下数据来自构造手机记录。它们包含完整且较规则的字段，不能替代真实供应商表的算法效果或生产 PostgreSQL 压测。

| 范围 | 最终实现实测 |
| --- | --- |
| 1,000 来源 × 10,000 标准商品 | 全流程 4.53 秒；含 CSV 生成/解析、标准化、入库、首次索引和候选结果保存；峰值 RSS 269MB |
| 10,000 来源 × 50,000 标准商品 | 全流程 93.39 秒，成功处理 10,000 条、失败 0 条；峰值 RSS 775MB |
| 大容量取消 | 已完成 200 条后发起取消，0.22 秒进入 CANCELLED，工作线程停止 |
| 10 个模拟并发读取者 | 100 次列表请求，P95 747ms，100 次均 200；测试运行包含 29 条记录 |
| 10 个模拟并发审核者 | 10 次独立条目确认，P95 96ms，10 次均 201 |

网络上传时间未计入。API 并发测试通过进程内 ASGI TestClient，不包含网络和反向代理。参考方案为 4 核环境，本次 8 核 Mac 的成绩不能直接作为参考环境承诺。

首次实现使用 Python 对全部候选排序，标准规模为 8.40 秒。之后改用转置稀疏索引和数组排序，索引版本升级为 v2，最终标准规模为 4.53 秒。最终文件分别为 `benchmark-1000x10000-v2.json`、`capacity-10000x50000.json` 与 `api-load.json`。

## 模型准入未通过

Abt-Buy 官方测试集有 1,916 对记录，206 对为正样本。规则基线 F1 为 0.322，LightGBM 三个种子平均 F1 为 0.682，标准差 0.0043。预先指定导出的 seed 42 模型精确率 0.613、召回率 0.777。

这属于给定候选对分类实验，没有证明首选手机 SKU 推荐精确率达到 98%，也没有证明同精确率下端到端覆盖率收益。模型保持 EXPERIMENTAL，默认业务使用规则方案，正式映射始终人工确认。完整记录见 [模型实验报告](模型实验报告.md)。

## 未实测及实施差异

- Docker / PostgreSQL / Redis / Celery / MinIO 组合未在本机实际运行。交付了容器配置、持久卷、迁移、发件箱和 S3 接口，但这些组合测试需在有 Docker 的目标环境执行。Redis 故障测试采用注入的连接失败，不能替代真实网络分区实验。
- 未在 WDC 完整实体数据上实际执行独立检索评测。已提供数据登记、实体切分与 10% / 30% 无匹配构造工具，以及实体分组区间评测器；不能据此报告 Recall@20 ≥95%。
- 200 对中文样例由规则构造，尚未经两名业务人员独立核验。公开实验没有完成额外的未见实体分类评测和近重复人工审计，结果保留探索性标签。
- 导入解析与校验在有界 API 请求中同步执行，导入前限制 20MB、工作表、行列和单元格长度；匹配及导出在独立后台执行。相比方案的异步导入设计，这是首版实现的明确差异。
- API 关键列表提供游标分页；标准库目录和成员列表按组织完整返回，供应商批次选择当前最多返回 100 个批次。标准库商品和来源明细仍分页。后续扩大团队规模时应补全目录列表的分页。
- 导出到期后拒绝下载，当前未自动物理清理对象；原文件和历史引用资产保持保留。模型准入目前由离线报告及模型登记控制，页面仅提供规则方案创建，学习模型策略可通过 API 在模型获准后发布。
- 未完成 2–3 位真实业务人员的试用、业务演示录音、生产备份恢复或 RPO/RTO 演练；交付的是实际操作录屏，未声称真实企业采纳或节时收益。

P1 语义召回、历史映射自动复用、P2 深度微调和外部系统连接属于方案规定的后续范围，没有以占位按钮冒充已完成功能。
