# 手机 SKU 标注与试用规范

版本 1.1，2026-09-10。本次交付未招募标注者或试用者，未记录人工试用成果。下面是可直接执行的采集与验收规则。

## 数据与标注

本次提供 `ml/datasets/phone-sim-v1/manifest.json`：400 个虚构 SKU 实体中移除 40 个实体的全部标准记录，保留 360 个候选标准商品，提供 1,200 条查询。型号、配置和价格用于受控模拟，不是厂商商品事实或客户数据。生成器先分配实体真值，再生成格式扰动、缺字段和冲突；不读取匹配器输出生成标签。

真实数据采集时，登记授权来源、用途、许可范围、获取日期及文件 SHA-256。类型为 `licensed_public` 或 `authorized_supplier`；`license` 写明授权条件。未经授权的数据不进入可分发数据包。

每条查询的最小字段：`query_id/id`、`entity_id`、`series`、`catalog_version`、`source`、原始 `fields`、`catalog_exists`、`match_evidence`、`annotators`、`review_status`、`partition`、`slices`。示例结构如下，仅展示格式，姓名和标签不可复制充当人工记录：

```json
{
  "annotators": [
    {"id": "实际标注者编号", "type": "human", "entity_id": "独立判断的实体编号", "catalog_exists": true}
  ],
  "review_status": "PENDING",
  "match_evidence": "供应商规格文件或可追溯的产品资料"
}
```

两位标注者分别看原始商品资料和候选库，先独立提交，再进行对照。不得向标注者展示模型建议作为真值来源。二人一致后标记 `AGREED`；不一致交由第三人或指定复核者处理，记录 `adjudicator` 后标记 `ADJUDICATED`。未完成记录不属于冻结测试。标注不能仅凭相似名称；逐项核对品牌、型号、RAM、存储、颜色、地区、包装。

同一完整 SKU 的别名与近重复必须归入同一实体和分区。冻结 `train / tuning / calibration / threshold / test` 五个互斥实体分区，另设整型号系列 `series_holdout`。测试实体可以存在于固定候选库；训练词表只拟合训练查询与训练实体商品。人工近重复审查完成后登记 `provenance.near_duplicate_review=completed`；存档审查明细。

无匹配查询保留自己的原始实体编号，声明 `catalog_exists=false`，核对该实体全部标准记录均已从候选库移除，并保留相近规格干扰项。仅删除一条正例配对不符合规则。冻结后写入版本、配置和数据哈希，不再使用测试查询调参或挖训练负样本。

验证与评测：

```bash
python -m ml.eval.retrieval ml/datasets/phone-sim-v1/manifest.json --partition test --output docs/optimization/phone-evaluation.json
python -m ml.train.phone_experiment
python -m scripts.verify_pipeline
python -m scripts.evaluate_policy models/phone-sim-v1/bundle.json ml/datasets/phone-sim-v1/manifest.json --org-id 实际组织ID --name 手机实体评测
```

上述模拟数据即使点估计达到目标也无法通过业务准入。建议有限人工必审试用门槛：Recall@20 ≥95%、推荐精确率 ≥98%、覆盖率 ≥30%、无匹配误推荐率 ≤1%，且至少 200 个独立推荐实体。稳定 98% 声明还须预先约定的 95% 区间下界 ≥98%。无推荐记为不可估计。实体 bootstrap 零错误时补充实体 Wilson 区间，保守区间用于准入声明；无匹配按独立实体计算补充二项区间，避免同实体多条查询被当作独立样本。

## 小规模试用

招募 2–3 位采购、商品运营或熟悉表格的参与者。若参与者为同学，只记录为可用性试验。每人使用两个难度相近的 50–100 条数据集；A 先表格后平台，B 先平台后表格，C 用随机顺序。清单含缺字段、规格冲突、正确候选、无候选及人工搜索场景，并控制各类比例。

计时从打开资料开始，到提交有效审核结束；记录中断和资料等待，不悄悄排除耗时样本。平台已采集选中记录至提交审核的耗时、人工搜索和补数保存次数。管理员在“组织设置 → 策略评测”查看任务级中位耗时与次数。遥测只能说明操作情况；误确认必须由独立复核者核对最终映射。

为每次试用填写 `docs/试用记录模板.csv`：参与者编号、类型、任务、方法、顺序、开始与结束时间、总时长、审核数、误确认数、搜索次数、补数往返次数、中断原因。不要填入虚构参与者。保留原始记录，报告每位参与者配对差异与总体中位数。只有实测达到时才描述“降低 30% 耗时”，同时给出人数、样本量及误确认变化。

当前没有真实试用记录，因此没有节省时间、误确认率或企业使用效果的结论。
