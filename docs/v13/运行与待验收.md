# v1.3 运行与待验收

应用与操作说明见本目录“使用说明”；历史 v1.2 文档保留用于追溯。本页记录 v1.3 的运行差异及需要在企业环境执行的项目。

## 本地升级与启动

在项目根目录、已安装 `requirements.lock` 的 Python 环境中执行。先停止本项目旧 API 和 Worker，保存旧应用包及原配置。备份目录必须是新的目录。

```bash
python -m scripts.upgrade --backup /path/to/new-v13-backup
DB_AUTO_CREATE=false python -m scripts.backfill_v13
DB_AUTO_CREATE=false python -m alembic check
DB_AUTO_CREATE=false python -m scripts.dev --port 18765
```

升级会验证已知结构并自动备份，目标迁移头为 `b86fd0144e45`。未知未标版本结构会停止并保留备份；应比较实际索引与迁移，不能直接盖章跳过。`backfill_v13` 为历史发布生成增量物化，并为输入版本生成质量快照，原发布 CSV 字节保留。

`DATA_DIR` 指向业务目录；没有显式 `DATABASE_URL` 时默认读取其中 `app.db`。保留原 `session.key`、`JWT_SECRET` / `INTEGRATION_MASTER_KEY` 配置、对象文件和模型目录。不要用 `--seed`、测试脚本或新密钥替换现场数据。

健康入口：`/api/v1/live` 检查进程，`/api/v1/health` 检查数据库，`/api/v1/readiness` 检查数据库、队列和存储。v1.3.1 中 Redis 或对象存储不可用时 readiness 返回 503；OpenAPI 中应用版本应为 `1.3.1`。

回退优先判断是否可仅回退应用；已产生新发布/回执时不直接降级数据库。确需恢复时使用完整备份到新目录，核对新产生业务与下游状态后再切换，原目录保留。

## 日志与业务监控

默认 Uvicorn 启动会输出结构化请求日志。每条包含 `request_id/trace_id`、路由、HTTP状态、响应字节、SQL次数与执行时间、连接获取、锁语句和JSON编码时间。慢SQL只保留形状哈希，不记录参数。部署时保留 INFO 日志及时间戳；若改成 WARNING 级别，请求日志不会输出。

连接获取包含建连/签出/初始化，锁语句时间包含语句工作，二者均不是 PG 内部等待事件的精确替代。发生慢请求时，先按请求编号定位分段，再在独立目标验收库中用实际参数执行 `EXPLAIN (ANALYZE, BUFFERS)` 并核对等待事件。精确SKU、型号前缀、中文短词/短型号、名称包含分别测量；是否启用 `pg_trgm` 与 GIN 索引由执行计划和写入成本决定。

监控文件位于 `deploy/compose.monitoring.yaml`、`deploy/prometheus.yml`、`deploy/alerts.yml`。新增回执超期、发布文件长期未就绪、影响长期未关闭、供应商资料未补齐和接收端责任人未配置告警。指标入口采用专用凭据，监控需覆盖每个 API 和 Worker 实例。多API的持久业务量使用去重聚合，不能把同一业务量按实例求和。

SQLite 新建匹配任务每块50条，PostgreSQL每块200条；已存在任务继续使用原分块。结果与候选按有界批次写入，整个分块保持同一事务和租约/令牌校验。SQLite每连接默认64MiB页缓存预算，可用 `SQLITE_CACHE_MIB` 在1–256之间配置；应结合连接数估算总内存。Worker日志记录已提交分块的准备、持久化及事务完成时间，事务完成包含最后flush和commit。

回执扫描每30秒执行，每轮最多处理100条。超过一轮容量时会继续积压至下一轮，持续超期指标用于提示负责人排查。现有配置尚未实际启动 Prometheus/告警接收渠道；MinIO空间、整机磁盘和日志保留应在目标环境单独采集。处理人及升级路径由实际部署团队填写。

## 本地恢复与交付暂停

```bash
python -m scripts.backup create /path/to/new-backup
python -m scripts.backup verify /path/to/new-backup
python -m scripts.backup restore /path/to/new-backup /path/to/fresh-restore
DATA_DIR=/path/to/fresh-restore MODEL_DIR=/path/to/fresh-restore/models DB_AUTO_CREATE=false python -m scripts.dev --port 18766
```

命令需沿用原密钥配置。环境变量提供的恢复密钥位于备份私有文件中，由运维按权限恢复，不能提交到源码包。若恢复目录出现 `delivery-restore-hold.json`，后台暂停发送待交付通知。按原事件号、对端实际应用发布、基线及摘要逐条对账，记录依据后才运行现有 `scripts.reconcile_restore` 流程解除暂停。

本轮本地恢复证据见 `restore.json`，没有测量PG/MinIO的丢失窗口。企业环境需配套保存数据库备份/日志、对象存储、模型、词表、配置和密钥，以一次明确的恢复点恢复至独立环境，实测备份时间、数据丢失窗口、复制/导入/验证及业务恢复用时。RPO≤24小时、RTO≤2小时为待验收起点。

## 目标栈执行清单

本机缺少 Docker/Podman/Colima、PostgreSQL、Redis、Prometheus，可用性记录见 `environment.json`。尚未获得企业远端目标环境，因此下列项目保持“待执行”。配置文件和CI步骤不等于执行证据。

| 场景 | 需完成的操作与留存证据 |
| --- | --- |
| 固定制品部署 | 构建 `compose.yaml` 与 `deploy/compose.acceptance.yaml`，记录应用提交、依赖锁、真实镜像摘要、配置摘要和资源限额；迁移后禁用自动建表 |
| 生产式完整流程 | 在独立组织数据上完成导入、多人审核、补数、影响处置、完整发布、下载、下游回执；核对行数与摘要 |
| PG事务及故障 | 并发审核、领取、发布、身份绑定；中断与恢复PG后验证无半份决定/错误关闭/重复有效发布；实际SQL计划和等待事件 |
| 真实Celery/Redis | 终止实际正在执行的子进程，不人工缩短租约；自然恢复后验证旧令牌拒绝、没有重复有效结果；Redis中断和恢复 |
| MinIO中断 | 文件生成途中中断对象存储，未就绪制品不能下载或交付；恢复后重试并核对原快照哈希 |
| 持续容量 | 约定资源、真实数据特征和节奏，至少30分钟持续组织队列、正式发布/下载混合；保存冷/稳态、逐请求、所有实例资源与阶段时间 |
| 告警到人 | 指定处理人和渠道，实际触发、收到通知、定位、恢复并解除，保存时间线 |
| 生产式恢复 | PG、对象、模型、密钥恢复至独立环境；验证文件、历史、隔离、待交付对账及RPO/RTO |
| 真人与真值 | 2–3位业务参与者按“真人试用与目标数据采集”记录有效时间、等待、错误与返工；取得授权目标数据和独立完整真值 |

如真实ERP暂不可接入，可约定仅人工文件交付的试用范围；这不构成自动ERP链路验收。当前模拟接收端仅用于协议检查，不自动写入真实采购系统。

## 复现本轮证据

在隔离测试目录中执行后端检查：

```bash
python -m pytest -q
TEST_MIGRATED_SCHEMA=true DB_AUTO_CREATE=false python -m pytest -q
pnpm -C apps/web build
```

保留旧数据升级的业务验证入口为 `scripts.verify_v13_upgrade`；标准库规模为 `scripts.v13_catalog_benchmark`；最终容量为 `scripts.v13_load`，要求已准备两组织50k/10k构造夹具及应用迁移结构。后者的2个流程驱动会持续生成运行与发布，请只在专用验收目录中使用。正式运行前冻结代码，发生运行逻辑或关键性能变更后重跑受影响证据。

CI 的 PostgreSQL 任务使用迁移结构运行测试，不执行表重建fixture；本次未在远端CI运行。所有历史文件和报告应保留版本归属，避免把旧负载结果算到新制品。

## v1.3.1 数据库验收自动化

本轮新增 `scripts.acceptance_dataset`、`scripts.database_acceptance`、`scripts.stack_drill` 和 `scripts.verify_postgres_restore`。详细的账号、密钥、执行命令、证据目录与联合恢复步骤见 [数据库部署与验收说明](../v13-database/部署与验收说明.md)。本机静态预检与本轮结论见 [数据库优化验收报告](../v13-database/验收报告.md)。

`stack_drill` 只允许使用全新输出目录，并为每次运行创建唯一 Compose 项目。私密凭据保存在证据目录之外的 `-private` 同级目录；默认清理成功后将证据文件设为只读。验收栈不会读取本地 `var/app.db` 或 `var/objects`。
